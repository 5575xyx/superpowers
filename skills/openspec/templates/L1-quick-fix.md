# L1 - 快速迭代流程模板

> 级别：L1
> 名称：快速迭代（Quick Fix）
> 适用：小功能、小优化、Bug修复、单模块小改动
> 预计耗时：< 30 分钟
> 文档产出：tasks.md（简化版）

---

## 流程步骤

### Step 1: 快速设计（5 分钟）

**快速回答以下问题：**
- [ ] 要解决什么问题？
- [ ] 改动哪些文件/模块？
- [ ] 大概的实现思路？
- [ ] 需要写测试吗？
- [ ] 有什么风险点？

**记录：** 在脑中或快速记几句话即可，不需要完整设计文档

### Step 2: 快速规划

**创建简化版 tasks.md：**
```markdown
# Tasks: {{任务名称}}

> 级别：L1 - 快速迭代
> 预计耗时：< 30 分钟

## 任务清单

- [ ] Step 1: 实现功能
- [ ] Step 2: 编写测试
- [ ] Step 3: 运行测试
- [ ] Step 4: 快速自审
```

### Step 3: 实现代码

- [ ] 按规划实现功能
- [ ] 保持代码简洁
- [ ] 遵循项目代码风格

### Step 4: 编写测试

- [ ] 至少编写核心测试用例
- [ ] 覆盖正常流程
- [ ] 覆盖主要边界条件

### Step 5: 运行测试

- [ ] 所有测试通过
- [ ] 没有回归问题

### Step 6: 快速自审（L1 自审）

**检查清单：**
- [ ] 代码是否正确实现了需求？
- [ ] 有没有明显的 bug？
- [ ] 测试是否充分？
- [ ] 代码风格是否符合项目规范？
- [ ] 有没有引入不必要的复杂度？

**如果自审发现问题 → 回去修改**
**如果自审通过 → 继续**

### Step 7: 提交

**Commit message 格式：**
```
{{type}}: {{简短描述}}

改动类型：L1 - 快速迭代
影响范围：{{模块/文件}}
风险等级：低
测试状态：{{通过/部分通过}}
```

## L1 流程检查清单

### 进入条件
- [x] 改动量 10-50 行
- [x] 单模块内修改
- [x] 小功能/小优化/Bug 修复
- [x] 风险等级低

### 执行步骤
- [ ] Step 1: 快速设计
- [ ] Step 2: 快速规划
- [ ] Step 3: 实现代码
- [ ] Step 4: 编写测试
- [ ] Step 5: 运行测试
- [ ] Step 6: 快速自审
- [ ] Step 7: 提交

### 退出条件
- [x] 功能实现完成
- [x] 测试通过
- [x] 自审通过
- [x] 代码已提交

---

## 何时需要升级到 L2+

如果在执行过程中发现以下情况，立即升级：

- 改动超过 50 行 → 升级到 L2
- 涉及多个模块 → 升级到 L2
- 需要设计决策 → 升级到 L2
- 风险等级中等以上 → 升级到 L2
- 需要文档记录 → 升级到 L2
- 用户要求完整流程 → 升级到 L2+

---

## 何时可以降级到 L0

如果发现：
- 实际改动 < 10 行
- 只是 typo/配置/文案
- 不需要测试

**可以降级到 L0 流程**

---

**记住：** L1 是效率和质量的平衡点。如果有任何不确定，立即升级到更高级别。
