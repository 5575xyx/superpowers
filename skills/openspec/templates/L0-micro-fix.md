# L0 - 微型修复流程模板

> 级别：L0
> 名称：微型修复（Micro Fix）
> 适用：修复 typo、调整配置、改文案、极小改动
> 预计耗时：< 5 分钟
> 文档产出：无（或仅 commit message）

---

## 流程步骤

### Step 1: 确认改动范围

**快速检查：**
- [ ] 改动是否 < 10 行代码？
- [ ] 是否只涉及单个文件？
- [ ] 是否是纯配置/文案/typo 修复？
- [ ] 是否不影响核心功能？
- [ ] 是否不涉及架构变更？

**如果以上全部是 → 继续 L0 流程**
**如果任何一个否 → 评估是否升级到 L1+**

### Step 2: 直接修改代码

- [ ] 修改代码
- [ ] 确保修改正确
- [ ] 不引入新的问题

### Step 3: 快速验证

**验证方式（任选其一即可）：**
- [ ] 快速运行相关测试
- [ ] 手动验证功能正常
- [ ] 确认语法正确
- [ ] 检查没有破坏性变更

### Step 4: 提交

**Commit message 格式：**
```
fix: {{简短描述}}

改动类型：L0 - 微型修复
影响范围：{{文件/模块}}
风险等级：极低
```

- [ ] 提交代码
- [ ] （可选）推送到远程

---

## L0 流程检查清单

### 进入条件
- [x] 改动量 < 10 行
- [x] 单文件修改
- [x] 纯配置/文案/typo
- [x] 不影响核心功能

### 执行步骤
- [ ] Step 1: 确认改动范围
- [ ] Step 2: 直接修改代码
- [ ] Step 3: 快速验证
- [ ] Step 4: 提交

### 退出条件
- [x] 修改完成
- [x] 验证通过
- [x] 代码已提交

---

## 何时需要升级到 L1+

如果在执行过程中发现以下情况，立即升级：

- 改动超过 10 行 → 升级到 L1
- 涉及多个文件 → 升级到 L1
- 需要修改测试 → 升级到 L1
- 影响业务逻辑 → 升级到 L2
- 发现潜在风险 → 升级到 L2
- 用户要求完整流程 → 升级到 L2+

---

**记住：** L0 是为了效率，但安全第一。如果有任何不确定，立即升级到更高级别。
