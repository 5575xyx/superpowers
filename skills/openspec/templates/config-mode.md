# Config Mode - 配置修改模式

> 适用场景：纯配置修改、参数调整
> 预计耗时：5-15 分钟

---

## 触发条件

满足以下条件，自动进入 Config Mode：

- 只修改配置文件
- 不涉及代码逻辑
- 不涉及功能变更
- 修改的是配置参数、环境变量、阈值等
- 用户明确要求 "改个配置"、"调个参数"

---

## 流程步骤

### Step 1: 确认修改范围

- [ ] 确认是纯配置修改
- [ ] 确认不涉及代码逻辑
- [ ] 确认修改的配置项
- [ ] 评估修改的影响范围

### Step 2: 修改配置

- [ ] 修改配置文件
- [ ] 保持配置格式正确
- [ ] 添加必要的注释

### Step 3: 验证配置

- [ ] 语法验证（JSON/YAML/ENV 格式正确）
- [ ] 逻辑验证（值是否合理）
- [ ] （如需要）本地测试验证
- [ ] （如需要）启动应用验证

### Step 4: 提交

- [ ] 提交配置变更
- [ ] 记录修改原因和影响

---

## 配置修改检查清单

### 修改前
- [ ] 理解配置项的作用
- [ ] 知道默认值和推荐值
- [ ] 了解修改后的影响
- [ ] 确认有回滚方案

### 修改中
- [ ] 配置格式正确
- [ ] 值在合理范围内
- [ ] 有必要的注释说明
- [ ] 敏感信息未硬编码

### 修改后
- [ ] 语法验证通过
- [ ] 应用能正常启动
- [ ] 功能表现符合预期
- [ ] 文档已同步更新

---

## Commit Message 格式

```
config: {{配置修改简短描述}}

标签：config / parameter / settings
修改项：
  - {{配置项1}}: {{旧值}} → {{新值}}
  - {{配置项2}}: {{旧值}} → {{新值}}
影响范围：{{说明影响哪些功能}}
验证方式：{{已验证 / 待验证}}
```

---

## 常见配置类型

| 类型 | 示例 | 风险等级 | 验证要求 |
|------|------|----------|----------|
| 功能开关 | feature flags | 低 | 验证开关正常工作 |
| 阈值参数 | 超时时间、重试次数 | 低 | 验证值合理 |
| 环境配置 | API 地址、端口 | 中 | 验证连通性 |
| 安全配置 | 密钥、权限 | 高 | 严格验证 |
| 性能参数 | 连接池、缓存大小 | 中 | 性能测试验证 |

---

## 注意事项

### ✅ 可以跳过的

- 完整设计文档
- 单元测试（配置本身不需要测试）
- 红队审查
- 需求追踪

### ❌ 不能跳过的

- 配置格式验证
- 影响范围评估
- 回滚方案准备
- 修改记录

---

## 何时升级到标准流程

如果发现以下情况，立即升级：

- 配置修改需要代码配合
- 修改涉及核心安全配置
- 配置项有不确定的副作用
- 需要新增配置项（而不是修改现有值）
- 修改影响多个模块

---

**记住：** 配置虽小，影响可能很大。
特别是安全配置和核心参数，必须谨慎。
当有任何不确定时，升级到更高阶的流程。
