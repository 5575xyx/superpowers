# Doc Mode - 文档更新模式

> 适用场景：纯文档更新、文档修复、补充文档
> 预计耗时：5-30 分钟

---

## 触发条件

满足以下条件，自动进入 Doc Mode：

- 只修改文档文件
- 不涉及代码逻辑
- 不涉及功能变更
- 修改的是 README、文档、注释、说明等
- 用户明确要求 "改个文档"、"更新文档"

---

## 流程步骤

### Step 1: 确认修改范围

- [ ] 确认是纯文档修改
- [ ] 确认不涉及代码
- [ ] 确认要修改的文档
- [ ] 明确修改目标

### Step 2: 修改文档

- [ ] 按目标修改文档
- [ ] 保持文档格式一致
- [ ] 检查拼写和语法
- [ ] 确保链接正确

### Step 3: 验证文档

- [ ] 文档格式正确（Markdown 等）
- [ ] 内容准确无误
- [ ] 代码示例正确（如有）
- [ ] 链接可访问（如有）

### Step 4: 提交

- [ ] 提交文档变更
- [ ] 记录修改内容

---

## 文档修改检查清单

### 修改前
- [ ] 理解文档的受众
- [ ] 明确修改的目的
- [ ] 找到相关的所有文档（可能有多处需要同步更新）

### 修改中
- [ ] 语言清晰准确
- [ ] 格式一致
- [ ] 术语统一
- [ ] 代码示例可运行（如有）

### 修改后
- [ ] 通读一遍
- [ ] 检查拼写错误
- [ ] 验证链接
- [ ] 确认没有遗漏相关文档

---

## Commit Message 格式

```
docs: {{文档修改简短描述}}

标签：docs / documentation / update
修改文件：
  - {{文件1}}
  - {{文件2}}
修改类型：{{新增 / 更新 / 修复 / 删除}}
影响范围：{{说明哪些读者会受影响}}
```

---

## 常见文档类型

| 类型 | 示例 | 风险等级 | 验证要求 |
|------|------|----------|----------|
| README | 项目说明 | 低 | 信息准确 |
| API 文档 | 接口说明 | 中 | 与代码一致 |
| 架构文档 | 设计说明 | 中 | 与实现一致 |
| 教程/指南 | 使用指南 | 低 | 步骤正确 |
| 注释 | 代码注释 | 低 | 准确有用 |
| 变更日志 | Release Notes | 中 | 完整准确 |

---

## 注意事项

### ✅ 可以跳过的

- 完整设计流程
- 单元测试
- 红队审查
- 需求追踪
- TDD 流程

### ❌ 不能跳过的

- 文档准确性验证
- 相关文档同步更新
- 拼写和格式检查
- 修改记录

---

## 何时升级到标准流程

如果发现以下情况，立即升级：

- 文档修改需要代码配合
- 文档描述了新功能（意味着需要实现）
- 文档涉及架构设计变更
- 需要新增大量文档（> 1000 字）
- 文档是用户可见的重要文档

---

**记住：** 文档是项目的脸面。
虽然文档修改不需要代码流程，但质量不能打折扣。
准确、清晰、完整的文档是优秀项目的标志。
