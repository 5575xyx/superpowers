# Bugfix Mode - 紧急修复模式

> 适用场景：生产环境 Bug 紧急修复
> 核心理念：先解决问题，后补流程文档
> 预计耗时：15-60 分钟（取决于 Bug 严重程度）

---

## 触发条件

满足以下条件之一，自动进入 Bugfix Mode：

- 生产环境出现问题，需要紧急修复
- 用户明确要求 "快修"、"hotfix"、"紧急"
- Bug 影响用户使用，需要尽快上线
- 有明确的故障现象和复现步骤

---

## 流程步骤

### Phase 1: 快速诊断（5-15 分钟）

**目标：** 快速定位问题根因

- [ ] 确认 Bug 现象和影响范围
- [ ] 快速复现问题
- [ ] 定位根因（代码/配置/数据/依赖）
- [ ] 评估修复难度和时间
- [ ] 判断是否需要回滚 vs 修复

### Phase 2: 快速修复（10-30 分钟）

**目标：** 尽快修复问题

- [ ] 编写修复代码
- [ ] 本地验证修复有效
- [ ] 编写/补充测试用例
- [ ] 运行相关测试确保无回归
- [ ] 快速自审代码质量

### Phase 3: 提交发布（5-10 分钟）

**目标：** 快速发布修复

- [ ] 提交代码（标记 hotfix）
- [ ] 推送到远程
- [ ] （如有）触发 CI/CD 部署
- [ ] 验证生产环境修复生效

### Phase 4: 事后补全（24 小时内）

**目标：** 补全流程文档，确保质量

- [ ] 补充 Bug 分析报告（根因、影响、修复方案）
- [ ] 补充完整测试用例
- [ ] 补充设计文档（如涉及架构调整）
- [ ] 更新知识库（经验教训）
- [ ] （如需要）创建后续优化任务

---

## 与标准流程的对比

| 维度 | 标准流程（L2+） | Bugfix Mode |
|------|----------------|-------------|
| 设计阶段 | 完整设计 + 审查 | 快速诊断 + 修复方案 |
| 文档产出 | 全套文档 | 事后补全 |
| 审查环节 | 多轮审查 | 快速自审 + 事后补审 |
| 测试要求 | 完整测试覆盖 | 核心验证 + 事后补充 |
| 时间要求 | 充分设计，一次做对 | 快速修复，质量次之 |
| 知识库更新 | 归档时更新 | 24 小时内补全 |

## Commit Message 格式

```
fix: {{Bug 简短描述}}

标签：hotfix / urgent / bugfix
影响范围：{{模块/功能}}
严重程度：{{critical / major / minor}}
根因分析：{{简述根因}}
修复方案：{{简述修复方案}}
测试验证：{{已验证 / 待补充}}
```

---

## 注意事项

### ✅ 可以跳过的

- 完整的设计文档（事后补）
- 红队审查（事后补）
- 完整测试覆盖（核心验证即可，其余事后补）
- 跨引用文档（事后补）

### ❌ 不能跳过的

- 根因分析（必须理解问题）
- 核心功能验证（必须确认修复有效）
- 快速自审（不能引入新问题）
- 事后补全文档（24 小时内必须完成）

---

## 何时升级到标准流程

如果发现以下情况，立即升级到标准流程：

- 修复需要改动 > 100 行代码
- 涉及多个模块
- 需要架构调整
- 修复时间预计 > 1 小时
- 有潜在的副作用或风险
- 用户要求完整流程

---

**记住：** Bugfix Mode 是为了"快"，但不是为了"糙"。
快速修复是手段，质量保障是底线。
事后补全文档是必须的，不能省略。
