# Task Size Assessor - 任务规模评估

> 自动评估任务规模，推荐最合适的流程层级（L0-L4）
> 触发时机：用户提出开发/修改需求时，在进入具体流程前自动执行

---

## 五级流程体系

| 级别 | 名称 | 适用场景 | 核心步骤 | 文档产出 | 预计耗时 |
|------|------|----------|----------|----------|----------|
| **L0** | **微型修复** | 修复 typo、调整配置、改文案 | 直接改 → 验证 → 提交 | 无 | < 5分钟 |
| **L1** | **快速迭代** | 小功能、小优化、Bug修复 | 快速设计 → 实现 → 测试 | tasks.md | < 30分钟 |
| **L2** | **标准流程** | 中型功能、模块增强 | design + tasks + 自审 + 测试 | design + tasks | 1-2小时 |
| **L3** | **完整流程** | 大型功能、架构变更 | 完整 OpenSpec + 红队审查 | 全套文档 | 4-8小时 |
| **L4** | **重量级** | 核心架构、重大重构 | L3 + 多轮审查 + 用户确认 | 全套 + 评审记录 | 1天+ |

---

## 评估维度

从以下 6 个维度综合评估：

### 1. 代码改动量估算

| 等级 | 改动量 | 示例 |
|------|--------|------|
| **极小** | < 10 行 | 改一个变量名、修正 typo |
| **小** | 10-50 行 | 小 Bug 修复、简单配置 |
| **中** | 50-200 行 | 中型功能、模块增强 |
| **大** | 200-1000 行 | 大型功能、跨模块变更 |
| **极大** | > 1000 行 | 核心架构、重大重构 |

### 2. 影响范围

| 等级 | 影响范围 | 说明 |
|------|----------|------|
| **单点** | 1 个文件 | 只改一个文件 |
| **模块内** | 1 个模块 | 同一模块内多个文件 |
| **跨模块** | 2-3 个模块 | 涉及多个模块 |
| **系统级** | > 3 个模块 | 影响整个系统架构 |
| **全局** | 全系统 | 核心基础设施变更 |

### 3. 风险等级

| 等级 | 风险 | 说明 |
|------|------|------|
| **极低** | 配置/文案/typo | 几乎不可能出问题 |
| **低** | 非核心功能 | 出问题影响小，易回滚 |
| **中** | 普通业务功能 | 出问题有一定影响 |
| **高** | 核心功能 | 出问题影响大 |
| **极高** | 基础设施/安全 | 出问题可能导致系统瘫痪 |

### 4. 是否涉及核心架构

- **是**：架构设计、技术选型、基础设施
- **否**：业务逻辑、界面、配置

### 5. 需求清晰度

- **非常清晰**：需求明确，无歧义
- **基本清晰**：大体清楚，细节可能调整
- **模糊**：需要进一步澄清
- **探索性**：需要技术调研/原型验证

### 6. 用户明确要求

- **无**：用户未指定流程
- **快速**：用户要求快
- **完整**：用户要求走完整流程
- **重量级**：用户要求严格审查

### 7. 工作类型（通用化路由）

| 类型 | 说明 | 路由 |
|------|------|------|
| **编码** | 写代码、改代码、Bug 修复、功能实现 | 按 L0-L4 打分 |
| **文档** | README、API 文档、教程、注释 | 非编码轨道（grill-me → document 交付） |
| **产品 PRD** | 需求文档、产品方案、业务规则 | 非编码轨道（grill-me → document 交付） |
| **数据分析** | 数据处理、报表、统计分析 | 非编码轨道（grill-me → document 交付） |
| **运营流程** | 流程梳理、运营方案、配置 | 非编码轨道（grill-me → document 交付） |

**判定规则：工作类型为非编码 → 跳过 L0-L4 打分，直接路由非编码轨道**（grill-me 拷问 → 轻量任务清单 → 执行 → document 交付验证 → 归档）。

**小项目/个人项目**（编码类型但规模小、无团队协作、无审计需求）：默认压到 L0/L1，入口改为 grill-me，不自动创建 openspec 工件。

## 评估算法

### 评分表

| 维度 | L0 | L1 | L2 | L3 | L4 |
|------|----|----|----|----|----|
| 代码改动量 | <10行 | 10-50行 | 50-200行 | 200-1000行 | >1000行 |
| 影响范围 | 单点 | 模块内 | 跨模块 | 系统级 | 全局 |
| 风险等级 | 极低 | 低 | 中 | 高 | 极高 |
| 核心架构 | 否 | 否 | 否 | 可能 | 是 |
| 需求清晰度 | 非常清晰 | 非常清晰 | 基本清晰 | 基本清晰 | 模糊/探索 |

### 判定规则

1. **先判工作类型**：非编码 → 直接路由非编码轨道，不进入 L0-L4 打分；编码 → 继续以下规则。
2. **取最高维度的等级**：任何一个维度达到某级别，至少使用该级别
3. **向上取整**：如果多个维度在两个级别之间，取较高的级别
4. **用户要求优先**：用户明确要求的级别优先于自动评估
5. **安全/架构升级**：涉及安全或核心架构的，至少 L3

### 降级条件（满足以下所有条件可降级一级）

- 需求非常清晰
- 有类似功能的历史经验
- 有完善的测试覆盖
- 回滚容易

**注意：** 最多只能降级一级，不能降级两级或更多。

## 各级别流程触发的技能

### L0 - 微型修复
- **触发技能：** grill-me（可选用，快速澄清）→ 直接修改
- **验证：** 快速测试验证
- **文档：** 仅 commit message
- **审查：** 无

### L1 - 快速迭代
- **触发技能：** grill-me（入口拷问）→ writing-plans（简化）
- **验证：** 单元测试
- **文档：** tasks.md（简化版）+ 简短验收说明
- **审查：** L1 自审

### 非编码轨道（文档/PRD/数据分析/运营流程）
- **触发技能：** grill-me（入口拷问）→ 轻量任务清单 → 执行
- **验证：** 人工审阅 + 内容准确性检查（document 交付验证，不跑构建命令）
- **文档：** 标准变更结构（proposal/design/tasks/cross-reference/traceability），内容为文档/数据/PRD 而非代码
- **审查：** 用户确认
- **交付：** `powersnexus init delivery <name> --profile document` → `verify delivery` → `check delivery`
- **注意：** document profile 只豁免 build/test/integration/run/health 执行步骤；`check consistency` 仍要求 proposal/design/tasks/cross-reference 与 delta-specs 齐全，不能跳过（archive 门槛不变）

### L2 - 标准流程
- **触发技能：** brainstorming → writing-plans → test-driven-development
- **验证：** 完整测试 + 集成测试
- **文档：** design.md + tasks.md
- **审查：** 自审 + 代码专家审查

### L3 - 完整流程
- **触发技能：** brainstorming（完整）→ openspec → 红队审查 → subagent-driven-development → finishing
- **验证：** 完整测试 + 集成测试 + 性能测试
- **文档：** 全套 OpenSpec 文档
- **审查：** 红队设计审查 + 代码红队审查

### L4 - 重量级
- **触发技能：** L3 全部 + 探索模式 + 多轮用户确认 + 正式评审
- **验证：** L3 全部 + 压力测试 + 安全审计
- **文档：** L3 全部 + 架构决策记录 + 评审记录
- **审查：** 全员红队 + 双审查 + 用户终审

## 使用方式

### 自动触发

当用户提出开发/修改需求时，自动执行：

1. 快速分析需求
2. 从 6 个维度评估
3. 生成评估报告
4. 推荐流程级别
5. 等待用户确认（或自动执行，取决于置信度）

### 置信度与自动执行

| 置信度 | 动作 |
|--------|------|
| > 90% | 自动执行推荐级别，事后告知 |
| 70-90% | 给出推荐，等待用户一键确认 |
| 50-70% | 给出推荐 + 理由，等待用户确认 |
| < 50% | 询问用户，列出选项 |

## 边界场景处理

### 紧急修复 / Hotfix
- **自动升级一级**（安全考虑）
- 但简化非必要步骤
- 事后补文档

### 探索性工作
- 自动判断是否需要 exploration 模式
- 探索阶段独立，完成后再重新评估规模

### 文档更新
- 纯文档修改 → 非编码轨道（grill-me 入口），不再降级到 L0/L1
- 代码 + 文档同时修改，按代码评估

### 配置修改
- 纯配置修改，自动降级一级
- 涉及核心配置，保持原级别

### 个人/小项目
- 无团队协作、无审计/合规需求 → 默认压到 L0/L1，入口用 grill-me
- 用户后续要求完整流程 → 随时升级
